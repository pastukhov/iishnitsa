# Local suggestions on mobile

Open **Settings → Local suggestions** with an existing current chat and an explicit **Memory account ID**. This ID is a local namespace, not authentication. Each namespace/chat pair has separate consent, observations and drafts. Missing scope disables the panel. No web, Telegram or CLI controls are added.

Collection is off by default. After enabling **Collect local feedback**, the user may explicitly press **Too long**, **Too brief**, or **Length is right**. These three enums are the only evidence. Each observation has fixed `mobile_feedback` provenance, a day-bucket timestamp and a seven-day expiry. No message content, title, prompt, model/tool result, memory, skill content, endpoint URL or credential is read or collected. Nothing is sent to an external collector or scoring model.

Candidates are fixed reference templates for shorter or more detailed replies. They remain untrusted data. Each observation has weight `max(0, 1 - age / seven days)`. For each template, confidence is `max(0, (supportWeight - opposingWeight - neutralWeight) / (totalWeight + 2))`. At least two supporting marks and raw confidence >= 0.4 are required; display rounding cannot raise eligibility. Both conflicting feedback and “Length is right” reduce confidence. Fixed fictitious replay scenarios cover consistency, conflict, noise, decay and expiry.

**Review** displays the complete static draft and its source. **Save inactive draft** is a separate explicit action with a scope/storage/revision-bound, five-minute review ticket. Evidence changes, opt-out, expiry or deletion invalidate the ticket. Saving creates only a scoped, untrusted, inactive draft, retained for at most 30 days. There is no path to apply it to settings, prompts, skills, tool permissions, tasks or running agents. **Cancel review** stores nothing. Refresh recomputes eligibility; previously displayed confidence is only a snapshot.

Opt-out stops new feedback and invalidates outstanding consent/review revisions. Existing evidence/drafts remain until expiry or explicit deletion. **Delete observations and drafts** removes all observations and derivatives for that exact scope and disables collection. Other scopes are preserved. A durable monotonic revision prevents old actions from resurrecting deleted data after another opt-in.

Bounds: 32 scopes, 32 observations per scope (newest retained), two draft kinds and a 512K-character serialized document limit. Scope overflow fails instead of evicting someone else's data. Expired evidence/drafts are excluded and physically pruned on the next successful store access; no background job runs while the app is closed. Clear can free a scope slot. Corrupt or unsupported records are rejected without rewriting them; no legacy data migration occurs.

Storage operations serialize by adapter identity and reread the current document. Two stores targeting one backend must share the same adapter object (the native default does). Scope changes, unmounting or deleting the current chat abort pending panel work before persistence. Once native `setItem` has started it cannot be physically recalled; explicit feature deletion is serialized afterward. A failed write/clear is reported as unavailable, not success. Deleting a chat hides its suggestions and cancels pending work; use **Delete observations and drafts** before chat deletion to erase its retained feature data immediately, otherwise expiry cleanup occurs on later store access. No user-memory store or offline queue is modified.

Validation uses the actual mobile panel with real Zustand and mocked AsyncStorage, real store concurrency tests and fixed fake clocks. No real device data, native UI/emulator, external authentication, live providers or deployments were used. The feature is a local review aid, not an identity system or an autonomous learning agent.
