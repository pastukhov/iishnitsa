# Scoped MemoryStore (#201)

Evolve the existing @ai_agent_memory store. Active entries require an explicit accountId/chatId pair and provenance (explicit request, generated summary or deliberate import, with sourceId). These identifiers are caller-supplied namespaces, not authentication; credentials and legacy data never select a scope. Missing scope disables agent memory. Settings exposes an explicit account namespace and the current chat; changing scope clears stale views.

A shared in-runtime transaction queue reloads storage for every operation. Independent MemoryStore instances have no authoritative caches. Reads filter and sort without writes; lastAccessedAt is historical metadata, not a write-on-read trigger. Failures reject with fixed safe errors. This protects one JavaScript runtime, not simultaneous processes/devices writing AsyncStorage.

The same primary key becomes a version-2 envelope containing revision, scoped entries and quarantined legacy records. Pure reads of the old bare array expose no active memories. Explicit migration or the first mutation writes exact legacy bytes to @ai_agent_memory_legacy_backup before replacing the primary key. Retry never appends legacy records twice. Unknown/corrupt formats fail closed without replacing data. No record is assigned the currently selected account/chat. Export of unscoped legacy data is a deliberate management action; adoption is outside this slice.

Rollback restores original bytes only while migration revision is untouched and no scoped entries exist. Once new writes exist, rollback rejects rather than losing them. Scoped destructive operations first save an exact scoped backup (including expired records), then commit deletion/purge. Restore requires the expected post-operation revision, preserves original timestamps/TTL/provenance and rejects any intervening mutation. The latest backup per scope is retained; export it before further destructive actions. Neither global rollback nor restoration may erase another scope.

Active retention defaults to 30 days, is positive and at most 365 days. Expiry is exact at createdAt+ttlMs; reads omit expired entries without deleting them. Explicit purge deletes only the chosen scope after backup. Scoped exports include expired data for recovery. Limit content to4096 characters, identifiers to128, queries to256, results to100 and total active entries to1000; reject overflow rather than evict data. Exact caller-supplied ID retries are idempotent; conflicting same-ID writes reject.

Agent memory is separately serialized user-role reference data, never system instructions or a tool authority source. Scope is snapshotted per run before callbacks/fallback, shared AgentCore instances cannot mix it, and provenance distinguishes explicit user messages from generated summaries. Memory persistence errors after a successful answer are surfaced via a safe memory-error callback, not replayed as failed chat requests. Activated SKILL.md runs continue excluding all memory and queue persistence.

New offline payloads retain their explicit originating scope. Replay only matches the caller's current account/chat pair; mismatched entries remain queued. Legacy unscoped queued requests never acquire the current scope implicitly. No live migration or user data access is part of validation.

Alternatives rejected: per-instance writeback caches lose concurrent updates; automatic legacy attribution leaks context; silent purge-on-read erases data and races; clearing and re-adding entries for undo changes timestamps/retention and resurrects stale data. A cross-process database and account authentication are outside this issue.
