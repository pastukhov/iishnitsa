# Local mobile suggestions (#204)

Opt-in per exact local namespace and existing chat, off by default. Add a Settings panel for explicit feedback only: shorter, more detail, length OK. Do not observe chat, model/tool output, memory/skills, URLs or credentials. These fixed enums are the entire evidence payload, with fixed mobile-feedback provenance, day-bucket timestamp and seven-day expiry. No collector, scoring model, remote surface or agent/API integration.

Separate versioned local store, serialized by storage adapter identity and reread per transaction. Max 32 scopes (reject overflow, never evict another scope), 32 observations per scope (retain newest), two accepted draft kinds, 30-day draft TTL, 512K-character serialized document bound. Scope IDs use existing memory namespace/chat identity; this is local separation, not authentication. No existing user data migration. Invalid documents fail closed with fixed errors and remain untouched.

Candidates are static concise/detailed reference templates. Weight is max(0,1-age/7 days); confidence is max(0,(support-opposition-neutral)/(totalWeight+2)). Require two supporting observations and confidence >=0.4. All three signals enter totalWeight; contradictory and length-OK evidence reduces confidence. Age and noise deterministically lower confidence. Candidates and accepted drafts are untrusted data, never settings, prompts, skills or permissions.

A review ticket binds storage identity, exact scope, revision, kind and five-minute expiry. Separate explicit acceptance atomically stores an inactive draft, increments revision and consumes the ticket. No autoactivation or callback into execution. Declining review merely closes it; deletion clears all evidence and derived drafts, disables collection and retains a monotonic global revision so old leases/tickets cannot resurrect. Opt-out stops new collection and invalidates outstanding operations; retained evidence expires or can be explicitly deleted.

Panel resets and aborts outstanding work when namespace/chat changes or the chat is deleted. Recheck cancellation after storage awaits and immediately before writes. Once native setItem is invoked it cannot be physically undone; serialized explicit deletion runs after it and leaves no stale snapshot to resurrect. Display only snapshots from the current scope. Missing scope disables all controls.

Approaches: automatic chat-derived analytics would require unnecessary content access and weakly inferred preferences. A model-scored skill generator adds external processing and authority risks. Explicit bounded enum feedback with fixed drafts is the narrow supported choice. Real device/native storage/live services are not used for validation; real panel interaction uses mocked AsyncStorage and fictitious Zustand state.
